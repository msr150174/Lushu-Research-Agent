# 数据模型

> 配套文件：`01-接口契约.md`（API 出入参）、`03-溯源锚点规范.md`（锚点细则）
> 版本：v1.0 ｜ 生产：PostgreSQL ｜ 开发：SQLite（字段类型向下兼容）

---

## 设计原则（延续路书治理层）

1. **每条事实必须能追溯到原文位置** —— 没有 `anchor_id` 的断言不入库
2. **可信度显式分级** —— `原文` / `摘要` / `二手转述`，禁止混标
3. **缺口主动登记** —— 答不出的问题进 `unanswered_queries`，定期反哺
4. **版本可演进** —— 同一 arXiv 论文的 v1/v7 是两条记录 + 一条版本链

## 二、核心表

### 2.1 `paper_registry` —— 论文注册表

> 迁移自路书 `kb_docs`（doc_id → 文件名/采集日期/口径/可靠性）

```sql
CREATE TABLE paper_registry (
  paper_id        VARCHAR(32)  PRIMARY KEY,
  title           TEXT         NOT NULL,
  abstract        TEXT,
  arxiv_id        VARCHAR(32),                    -- 1706.03762
  doi             VARCHAR(128),
  version         INTEGER      DEFAULT 1,
  latest_version  INTEGER      DEFAULT 1,
  published_at    DATE,
  updated_at      TIMESTAMP,
  page_count      INTEGER,
  is_scanned      BOOLEAN      DEFAULT FALSE,     -- 是否 OCR 得来
  content_hash    VARCHAR(64)  NOT NULL,          -- ★ 正文语义去重依据
  pdf_sha256      VARCHAR(64),                    -- 原文件哈希
  file_path       TEXT,
  -- 迁移自路书 kb_docs 的治理字段
  source_site     TEXT,                           -- arXiv / ACL / IEEE
  collected_at    TIMESTAMP,
  scope           TEXT,                           -- 采集口径
  reliability     VARCHAR(16),                    -- 原文/摘要/二手转述  ★
  -- 解析状态
  parse_status    VARCHAR(16)  DEFAULT 'pending', -- pending/parsing/done/failed
  parse_error     TEXT,
  created_at      TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_paper_arxiv   ON paper_registry(arxiv_id, version);
CREATE INDEX idx_paper_hash    ON paper_registry(content_hash);
CREATE INDEX idx_paper_status  ON paper_registry(parse_status);
```

**`content_hash` 计算规则（官方用例 3.1 关键）**：

```
1. 抽取全文纯文本（去页眉页脚、去行号）
2. 规范化：小写、压缩空白、去除参考文献编号
3. 按 512 字符滑窗取指纹（SimHash / MinHash）
4. 与库中已有论文计算 Jaccard 相似度
5. 相似度 ≥ 0.90 判为重复
```

> ⚠️ **禁止用 `arxiv_id` 或文件名判重**。v1 与 v7 的 `arxiv_id` 完全相同，
> 只有基于**正文语义**才能识别"这是同一篇的不同版本"。

### 2.2 `paper_versions` —— 版本链

> 支持"库中已有更新版本，建议保留"与版本差异对比

```sql
CREATE TABLE paper_versions (
  id              SERIAL       PRIMARY KEY,
  paper_id        VARCHAR(32)  NOT NULL,          -- 指向 paper_registry
  version         INTEGER      NOT NULL,
  arxiv_id        VARCHAR(32),
  content_hash    VARCHAR(64)  NOT NULL,
  change_summary  TEXT,                           -- 与上一版的差异摘要
  diff_detail     JSON,                           -- [{type,section,detail}]
  is_latest       BOOLEAN      DEFAULT FALSE,
  created_at      TIMESTAMP    DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(paper_id, version)
);
```

### 2.3 `sections` —— 章节树（一/二/三级标题）

```sql
CREATE TABLE sections (
  section_id      VARCHAR(32)  PRIMARY KEY,       -- sec-3.2
  paper_id        VARCHAR(32)  NOT NULL,
  parent_id       VARCHAR(32),                    -- 上级章节
  level           INTEGER      NOT NULL,          -- 1/2/3
  title           TEXT         NOT NULL,
  page_start      INTEGER,
  page_end        INTEGER,
  order_index     INTEGER,
  FOREIGN KEY (paper_id) REFERENCES paper_registry(paper_id) ON DELETE CASCADE
);

CREATE INDEX idx_section_paper ON sections(paper_id, order_index);
```

### 2.4 `anchors` —— **锚点表（本项目灵魂）**

> 迁移自路书 `source_url`，颗粒度从"网页"细化到"PDF 页 + 坐标 + 字符区间"
> **详细规范见 `03-溯源锚点规范.md`**

```sql
CREATE TABLE anchors (
  anchor_id       VARCHAR(32)  PRIMARY KEY,       -- an_012
  paper_id        VARCHAR(32)  NOT NULL,
  section_id      VARCHAR(32),
  page            INTEGER      NOT NULL,          -- ★ 页码（1-based）
  bbox            VARCHAR(64),                    -- ★ "x0,y0,x1,y1" PDF 坐标
  char_span_start INTEGER,                        -- ★ 全文中的字符起点
  char_span_end   INTEGER,                        -- ★ 全文中的字符终点
  text            TEXT         NOT NULL,          -- 原文片段
  text_sha256     VARCHAR(64)  NOT NULL,          -- ★ 片段哈希，防篡改
  block_type      VARCHAR(16),                    -- paragraph/formula/table/figure/caption/title
  confidence      REAL         DEFAULT 1.0,       -- OCR 置信度（扫描件 < 1.0）
  is_ocr          BOOLEAN      DEFAULT FALSE,
  FOREIGN KEY (paper_id) REFERENCES paper_registry(paper_id) ON DELETE CASCADE
);

CREATE INDEX idx_anchor_paper ON anchors(paper_id, page);
CREATE INDEX idx_anchor_hash  ON anchors(text_sha256);
```

### 2.5 `chunks` —— 检索分片

> 长文档分级加载的关键（对应"渲染性能与内存优化 3%"）

```sql
CREATE TABLE chunks (
  chunk_id        VARCHAR(32)  PRIMARY KEY,
  paper_id        VARCHAR(32)  NOT NULL,
  anchor_id       VARCHAR(32),                    -- ★ 每个 chunk 必须挂锚点
  section_id      VARCHAR(32),
  level           VARCHAR(8)   NOT NULL,          -- doc / section / chunk （分级）
  text            TEXT         NOT NULL,
  token_count     INTEGER,
  page_start      INTEGER,
  page_end        INTEGER,
  embedding_id    VARCHAR(64),                    -- 向量库中的 id
  created_at      TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_chunk_paper ON chunks(paper_id, level);
```

**分级策略**：

| level | 内容 | 何时建 | 用途 |
|---|---|---|---|
| `doc` | 标题 + 摘要 | 上传即建 | 文献列表、粗筛 |
| `section` | 各章节整体（≤1.5k token） | 上传即建 | 目录导航、整段问答 |
| `chunk` | 段落级（512 token，重叠 64） | **按需懒加载** | 精细问答、溯源 |

> ⚠️ 541 页长书**禁止一次性全量建 chunk**，否则内存爆炸。
> 必须 `section` 全建 + `chunk` 首次访问该章时再建。

### 2.6 `references` —— 参考文献

> 支持正文 `[11]` ↔ References 双向跳转（交互创新 7%）

```sql
CREATE TABLE paper_refs (
  id                SERIAL       PRIMARY KEY,
  paper_id          VARCHAR(32)  NOT NULL,        -- 引用方
  ref_index         INTEGER,                      -- 正文中的 [11] 编号
  raw               TEXT         NOT NULL,        -- 原始条目文本
  ref_anchor_id     VARCHAR(32),                  -- References 区的锚点
  resolved_paper_id VARCHAR(32),                  -- 解析到库内论文
  resolved_arxiv_id VARCHAR(32),
  resolved_external TEXT,                         -- 外部链接
  citation_quality  VARCHAR(16),                  -- substantive / perfunctory ★
  created_at        TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_ref_paper ON paper_refs(paper_id, ref_index);
```

> `citation_quality` 用于"引用含金量"筛选——**自动剔除应付式引用**（模块四要求）。

### 2.7 `citation_edges` —— 引用图谱边

> 迁移自路书 `majors_positions`（关系表）

```sql
CREATE TABLE citation_edges (
  id          SERIAL       PRIMARY KEY,
  graph_id    VARCHAR(32),                        -- 所属图谱批次
  source_id   VARCHAR(32)  NOT NULL,              -- 引用方
  target_id   VARCHAR(32)  NOT NULL,              -- 被引方
  weight      INTEGER      DEFAULT 1,
  quality     VARCHAR(16),                        -- substantive / perfunctory
  context     TEXT,                               -- 引用上下文（"含金量"判断依据）
  created_at  TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_edge_graph ON citation_edges(graph_id);
```

**节点角色由图论算法计算后回写**：

```sql
CREATE TABLE graph_nodes (
  graph_id    VARCHAR(32),
  paper_id    VARCHAR(32),
  role        VARCHAR(16),     -- keystone / peripheral / normal ★
  pagerank    REAL,
  centrality  REAL,
  in_degree   INTEGER,
  out_degree  INTEGER,
  cluster     VARCHAR(32),
  PRIMARY KEY (graph_id, paper_id)
);
```

> `keystone` 判据建议：PageRank 前 20% 且 `in_degree` ≥ 中位数 2 倍。

### 2.8 `retraction_flags` —— 撤稿与学术风险（**本项目特色**）

> 迁移自路书 `mh_red_flags`（心理红灯 → 学术红灯）
> 对应 SAFETY 层最高优先级路由

```sql
CREATE TABLE retraction_flags (
  id          SERIAL       PRIMARY KEY,
  paper_id    VARCHAR(32),
  arxiv_id    VARCHAR(32),
  flag_type   VARCHAR(32)  NOT NULL,   -- retracted / expression_of_concern /
                                        -- predatory_journal / unverifiable /
                                        -- data_fabrication_suspect
  source      VARCHAR(64),              -- Retraction Watch 等
  source_url  TEXT,
  detected_at TIMESTAMP,
  severity    VARCHAR(16),              -- critical / warning
  action      VARCHAR(32),              -- block / warn / annotate
  detail      TEXT
);
```

> ⚠️ `severity = critical` 且 `action = block` 时，**任何引用该论文的回答必须被拦截**，
> 返回"该文献已被撤稿/存在风险，不作为依据"。这是 Guardrails 5% 的硬性实现。

### 2.9 `academic_sources` —— 数据源登记

> **直接迁移自路书 `data_sources`**，仅换内容

```sql
CREATE TABLE academic_sources (
  src_code    VARCHAR(16)  PRIMARY KEY,   -- A-1
  name        TEXT         NOT NULL,
  url         TEXT,
  status      VARCHAR(32),                -- 200 / 现行有效 / 已失效
  used_for    TEXT,                       -- 本系统用于
  level       VARCHAR(16),                -- 原文 / 摘要 / 二手转述
  checked_at  TIMESTAMP,                  -- 实测日期
  note        TEXT                        -- 坑位备注（如"旧链接 404，勿用"）
);
```

**初始数据（照抄即可）**：

| src_code | name | url | status | level | used_for |
|---|---|---|---|---|---|
| A-1 | arXiv API | `https://export.arxiv.org/api/query` | 200 | 原文 | 检索、元数据、PDF 下载 |
| A-2 | Semantic Scholar | `https://api.semanticscholar.org/graph/v1` | 200 | 原文 | 引用关系、影响力 |
| A-3 | ACL Anthology | `https://aclanthology.org/` | 200 | 原文 | NLP 论文全文 |
| A-4 | PubMed / bioRxiv | `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/` | 200 | 原文 | 生医领域 |
| A-5 | GitHub API | `https://api.github.com/` | 200 | 二手转述 | 开源代码复现性判定 |
| A-6 | Retraction Watch | `https://retractionwatch.com/` | 现行 | 原文 | 撤稿监测 |
| A-7 | UDL 官网 | `https://udlbook.github.io/udlbook/` | 200 | 原文 | 长文档测试 |

> 📌 **继承路书的"坑位记录"习惯**：
> 实测发现 arXiv abs 页 (`arxiv.org/abs/xxx`) 返回 HTML 需解析，
> 而 PDF 直链 (`arxiv.org/pdf/xxxvN`) 才是原件——**元数据走 abs，正文走 pdf**。

### 2.10 `unanswered_queries` —— 缺口登记

```sql
CREATE TABLE unanswered_queries (

```

> 💡 **这个表在决赛答辩时是加分素材**：

## 四、索引与向量库

| 存储 | 选型 | 说明 |
|---|---|---|
| 关系库 | PostgreSQL 15 / SQLite 开发 | 上述全部表 |
| 向量库 | **Chroma**（默认） | collection: `paper_chunks`，metadata 带 `paper_id/anchor_id/level` |
| 向量库（可选） | Milvus | 预留 `VectorStore` 抽象接口即可 |
| 缓存 | Redis（可选） | 检索结果缓存、会话 |

**Embedding 模型**：`BGE-M3`（多语言，中英论文通吃）
**Rerank 模型**：`bge-reranker-large`

## 五、初始化脚本要求

`db/init.sql` 必须：

1. 建全部表（SQLite/PostgreSQL 兼容写法，用 `VARCHAR` 不用 `TEXT[]`）
2. 插入 `academic_sources` 7 条初始数据
3. 建索引
4. 可重复执行（`CREATE TABLE IF NOT EXISTS`）

> ⚠️ 兼容性注意：
> - SQLite 无 `SERIAL` → 用 `INTEGER PRIMARY KEY AUTOINCREMENT`
> - 时间戳统一存 **UTC ISO8601 字符串**
> - `JSON` 字段在 SQLite 存 `TEXT`，PG 用 `JSONB`
