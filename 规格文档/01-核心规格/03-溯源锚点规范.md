# 溯源锚点规范（Source Tracing Spec）

> **本文件定义本项目的核心机制。抗幻觉 RAG 8% + Guardrails 5% 全靠它。**
> 版本：v1.0

---

## 一、为什么需要这套规范

赛道四原文要求：

> "知识问答的输出成果需明确标出**参考原文位置/段落**，防范大模型幻觉。"
> "对细粒度内容是否具备精准的**原文出处锚点（Source Tracing）**。"

**只给页码不够。** 模型可以编造"第 7 页说 8 块 GPU"，评委翻到第 7 页却发现没有——这就是幻觉。

本规范的目标是：**任何一条引用，都能被机器在 50ms 内验证真伪。**

## 二、锚点数据结构

### 2.1 完整锚点

```json
{
  "anchor_id": "an_012",
  "paper_id": "p_0001",
  "section_id": "sec-3.1",
  "page": 7,
  "bbox": [120, 340, 480, 392],
  "char_span": [1240, 1386],
  "text": "We trained on 8 NVIDIA P100 GPUs for 12 hours.",
  "text_sha256": "3f7a9c1e...",
  "block_type": "paragraph",
  "confidence": 1.0,
  "is_ocr": false
}
```

### 2.2 字段定义

| 字段 | 类型 | 含义 | 作用 |
|---|---|---|---|
| `anchor_id` | str | 全局唯一 | 前端跳转、后端校验的句柄 |
| `page` | int | 页码（**1-based**） | 人类可核对 |
| `bbox` | [x0,y0,x1,y1] | PDF 坐标系（**左下原点**） | **精确高亮定位** |
| `char_span` | [start,end] | 全文纯文本中的字符区间 | 机器比对 |
| `text` | str | 原文片段 | 显示给用户 |
| `text_sha256` | str | `text` 的 SHA256 | **防篡改** |
| `block_type` | enum | 段落/公式/表格/图/标题 | 分类展示 |
| `confidence` | float | 抽取置信度 | 扫描件标注 |
| `is_ocr` | bool | 是否 OCR 得来 | 提示用户"识别可能有误" |

## 三、`text_sha256` —— 防伪造的核心

### 计算规则

```python
import hashlib, re

def normalize(text: str) -> str:
    """规范化后再哈希，避免空格/换行差异导致误判"""
    t = text.strip()
    t = re.sub(r'\s+', ' ', t)          # 压缩空白
    t = t.replace('\u00a0', ' ')        # 不换行空格
    t = re.sub(r'-\s', '', t)           # 去连字符断行
    return t.lower()                    # 统一小写

def anchor_hash(text: str) -> str:
    return hashlib.sha256(normalize(text).encode('utf-8')).hexdigest()
```

### 校验流程（`/chat/verify-citation`）

```
用户看到引用 → 前端点击 → 后端校验
    │
    ├─ 1. 取 anchor_id 对应的 text_sha256
    ├─ 2. 对模型输出的 quoted_text 重新算哈希
    ├─ 3. 比对
    │     ├─ 一致 → valid: true  → 前端高亮该 bbox
    │     └─ 不一致 → valid: false → ★ 判定为幻觉引用，答案作废
    └─ 4. 记录到 call_logs
```

> **这是本项目最硬的技术壁垒。**
> 大部分参赛队只做到"给个链接"，我们做到"引用可被机器证伪"。

## 四、锚点生成流程

### 4.1 矢量 PDF（`1706.03762v1.pdf`）

```
PyMuPDF (fitz) 逐页解析
   ↓
page.get_text("dict") → blocks → lines → spans
   ↓
每个 block 生成 anchor：
   bbox        = block["bbox"]          （PDF 原生坐标，直接可用）
   text        = 拼接 spans 的 text
   page        = 页码（+1，转 1-based）
   char_span   = 在全文纯文本中的偏移   （累加计算）
   block_type  = 由字号/字重/位置推断
```

**公式识别**：检测 block 内含 Math 字体（`CMMI`、`CMMI7`、`CMSY`）或缺字 → 标 `formula`，用 PyMuPDF 的 `page.get_text("rawdict")` 提取。

### 4.2 扫描件（`1706.03762v1_img.pdf`）

```
PyMuPDF 渲染页面为 300 DPI 图
   ↓
PaddleOCR / Marker 识别
   ↓
识别结果带坐标（相对图片） → 按 DPI 换算回 PDF 坐标系
   ↓
confidence = OCR 置信度（必须如实写入，通常 0.85~0.97）
is_ocr = true
```

> ⚠️ **`is_ocr = true` 必须在 UI 上显式提示**：
> "本文献为扫描件，文字经 OCR 识别，可能存在偏差，请核对原文影像。"
> 这属于"诚实性设计"，比假装准确更得分。

### 4.3 长文档（541 页 UDL）

**分级策略**：

| 阶段 | 动作 | 内存 |
|---|---|---|
| 上传 | 只解析**目录 + 前 20 页**，建 `doc`/`section` 级 chunk | < 200MB |
| 首次访问某章 | 按需解析该章，建 `chunk` | +50MB |
| 未访问章节 | **完全不解析**，仅存页范围 | 0 |

> 这条直接对应"渲染性能与内存优化 3%"。

## 五、坐标系约定（**最容易出错的地方**）

| 场景 | 原点 | y 轴方向 | 说明 |
|---|---|---|---|
| **PDF 原生**（PyMuPDF `bbox`） | **左上** | 向下 | `y0 < y1` |
| **PDF 规范**（`fitz.Page.rect`） | 左下 | 向上 | 需转换 |
| **前端 PDF.js**（`viewport`） | 左上 | 向下 | 与 PyMuPDF 一致 |

**统一约定：全项目使用「左上原点、y 向下」，与 PyMuPDF 和 PDF.js 一致，避免来回转换。**

前端渲染时按缩放比换算：

```js
const scale = viewport.scale;
const rect = {
  left:   bbox[0] * scale,
  top:    bbox[1] * scale,
  width:  (bbox[2] - bbox[0]) * scale,
  height: (bbox[3] - bbox[1]) * scale,
};
```

## 六、可信度分级（延续路书 `source_level`）

| 取值 | 含义 | 判定依据 | UI 标注 |
|---|---|---|---|
| **`原文`** | 论文正文/Figure Caption 直接陈述 | `is_ocr=false` 且 来自正文 block | ✅ 绿色徽章"原文" |
| **`摘要`** | 仅来自 Abstract | `section_id == 'abstract'` | 🟡 黄色徽章"摘要" |
| **`二手转述`** | 来自综述、他人引用、GitHub README、搜索引擎摘要 | 非原始论文正文 | 🟠 橙色徽章"二手" |

### 铁律

> **把「摘要」或「二手转述」标注为「原文」= 数据造假。**
> 代码层面必须由数据来源自动判定，**不允许人工指定**。

判定代码位置：`backend/app/rag/attribution.py`

```python
def classify_level(anchor, section) -> str:
    if anchor.is_ocr:
        return "原文"        # OCR 但仍是原文，靠 confidence 提示
    if section and section["section_id"] == "abstract":
        return "摘要"
    if anchor.block_type in ("paragraph", "formula", "table", "caption"):
        return "原文"
    return "二手转述"
```

## 七、Guardrails 触发条件

| 触发类型 | 条件 | 动作 | 返回话术 |
|---|---|---|---|
| `no_source` | 检索结果为空，或 top1 相似度 < 0.45 | **拒答** | "现有资料未覆盖该问题。" |
| `low_confidence` | 0.45 ≤ top1 < 0.62 | 降级回答 | "以下内容基于相似度较低的片段，仅供参考：" |
| `retracted` | 命中的论文在 `retraction_flags` 且 `action=block` | **硬拦截** | "相关文献已被撤稿/存在风险，不作为依据。" |
| `conflict` | 多个锚点结论互相矛盾 | 显式提示 | "检索到互相冲突的结论：A 篇认为…，B 篇认为…" |
| `citation_unverified` | `text_sha256` 校验失败 | **答案作废** | "生成的引用无法在原文中定位，已作废该回答。" |
| `llm_fail` | 大模型 API 全部失败 | 降级到规则库 | 返回已检索到的原文片段，不做生成 |

### 三层降级链（迁移自 `智能无感/AiService.java`）

```
① 主大模型（DeepSeek / Qwen）        ← 首选
      ↓ 失败 / 超时（8s）
② 备用大模型（另一个 provider）      ← 兜底生成
      ↓ 失败
③ 纯检索模式（只返回原文片段）      ← 永不报错
```

> **关键**：第 ③ 层不生成任何新文字，只把检索到的原文片段列出来。
> 这符合"无出处则不答"的铁律——**宁可不答，不可瞎答。**

## 八、前端交互要求

### 引用卡片

```
┌─────────────────────────────────────┐
│ ✅ 原文   Attention Is All You Need v7 │
│ 📄 第 7 页 · §3.1                     │
│ ┌─────────────────────────────────┐ │
│ │ "We trained on 8 NVIDIA P100..." │ │

└─────────────────────────────────────┘
```

- 点击「定位到原文」→ 左侧 PDF 滚动到该页并高亮 `bbox`
- 点击「校验引用」→ 调 `/chat/verify-citation`，实时显示校验结果

### 双向跳转

- 正文中的 `[11]` 角标 → 点击 → References 区第 11 条高亮
- References 第 11 条 → 点击「被引位置」→ 回到正文所有 `[11]` 出现处

## 九、验收清单

模块二完成的标准（自测用）：

- [ ] 问"Attention 用了多少块 GPU"→ 答案带锚点，点击能高亮到原文
- [ ] 问论文里**不存在**的问题（如"作者是否提到量子计算"）→ 答"现有资料未覆盖"
- [ ] 篡改 `quoted_text` 后调 `/chat/verify-citation` → 返回 `valid: false`
- [ ] 上传一篇已撤稿论文 → 引用它的问题被 `retracted` 拦截
- [ ] 扫描件（`v1_img.pdf`）的引用带 `is_ocr: true` 提示
- [ ] 541 页长书首次访问某个未解析章节 → 不崩溃，按需加载成功

> **六条全过，模块二就算达标；否则 8% + 5% 的分数拿不稳。**
