# 迁移策略与正当性论证

> 本文件回答两个问题：
> ① **凭什么说这是"架构复用"而不是"改题目"？**
> ② **哪些资产能搬、搬成什么样？**
>
> 用途：可直接摘入技术文档的"创新点说明"与"AI 技术方案"章节。

---

## 一、核心论点（写进技术文档的原话）

> 本作品并非从零起建。团队此前在**垂直知识库 Agent**（高职学生职业规划场景）上已完整实践过一套治理架构，覆盖：
> **分层知识路由、来源可信度分级、无出处兜底协议、缺口闭环登记**。
>
> 该架构的核心命题是「**如何在开放域问答中保证事实确定性**」——这与科研文献助手的需求**同构**，区别仅在知识域与溯源颗粒度。
>
> 故本作品将该治理内核**迁移并升级**：知识域由职业岗位换为学术文献；溯源颗粒度由「表行级」细化至「PDF 段落级 + 坐标级」；并新增版本演进、引用图谱、学术护栏三项科研特有机制。

**这段话的价值**：把"我改了你的题"转化为"我有积累、我做了迁移"。在**科研场景创新性 25%** 里，这属于"技术方案的创新性"。

---

## 二、同构性论证（为什么迁移成本低）

| 维度 | 路书（职业规划） | 科研 Agent | 同构性 |
|---|---|---|---|
| **实体** | `positions` 岗位 JD | `paper` 论文 | 都是「实体 + 多段结构化属性」 |
| **属性分段** | 职责/技能/证书/薪资/路径（五段式） | 摘要/方法/实验/结论/局限 | 都是「固定分段抽取」 |
| **可信度分级** | `官方` / `市场` / `自建` | `原文` / `摘要` / `二手转述` | **完全同构** |
| **溯源** | `source_url` → 网页 | `page + bbox + char_span` → PDF | **同构（仅颗粒度更细）** |
| **时效** | `effective_from` / `effective_to` | `arxiv_version` / `published_at` | **完全同构** |
| **缺口管理** | `data_gaps`（15 条） | `unanswered_queries` | **完全同构** |
| **注册表** | `kb_docs`（3 册） | `paper_registry` | **完全同构** |
| **关系表** | `majors_positions` 专业→岗位 | `citation_edges` 论文→引用 | **完全同构** |

**表级复用率约 70%**，剩余 30% 为科研特有（PDF 解析、图谱算法、双向翻译）。

## 三、分层路由的重映射（最巧妙的一处）

路书原设计把 **SUPPORT（心理危机）设为最高优先级**，逻辑是「危机信号出现时，其他一切让路」。

迁移到科研场景后，这个优先级语义**天然成立**：

| 路书原层 | 原优先级 | 科研新层 | 新语义 |
|---|---|---|---|
| SUPPORT（心理危机） | **1（最高）** | **SAFETY** | **撤稿/学术不端/伦理风险 → 优先否决回答** |
| ACTION（岗位行动） | 2 | **METHOD** | 方法论、实验设计、指标定义、超参惯例 |
| FACT（学校事实） | 3 | **DOMAIN** | 领域论文事实（作者/机构/数据集/结论） |
| ALL（跨册） | 0 | **CROSS** | 多文献对比综述 |
| GOVERN（治理元数据） | 9 | **GOVERN** | 不变 |

**论证要点**：架构骨架一字未改，仅重新赋予语义。这说明该架构具有**跨域泛化性**——这正是"开源潜力与推广前景 5%"要考察的。

## 四、搬什么、不搬什么

### ✅ 直接搬（几乎零改动）

| 资产 | 来源 | 去向 |
|---|---|---|
| 「事实只来自知识库，无出处答未覆盖」铁律 | 各知识库头部 | `agent/guardrails/policy.py` |
| `source_level` 三级分类 | 职业规划库 §〇 | `paper_registry.reliability` + 引用标注 |
| `data_sources` 登记表结构 | `schema.sql` | `academic_sources` 表 |
| `data_gaps` 缺口表结构 | `schema.sql` | `unanswered_queries` 表 |
| `kb_docs` 文档注册表结构 | `schema.sql` | `paper_registry` 表 |
| 「已实测失效的坑」记录习惯 | 职业规划库 §一 注 | `docs/known-issues.md` |
| 三栏工作台 UI + 设计令牌 | `路书-VTJ工作台.json` | `frontend/src/` |
| 调用日志页 | `log` 页面 | Agent 可审计性展示（对应 6%） |
| 三层降级兜底思路 | `智能无感/AiService.java` | `agent/fallback_chain.py` |

### ⚠️ 改造后搬

| 资产 | 改造点 |
|---|---|
| `positions` 五段式 → `papers` 分段 | 五段改为：摘要/方法/实验/结论/局限 |
| `source_url` → 锚点 | 升级为 `page + bbox + char_span + text_sha256` |
| `salary_percentiles` → `benchmark_scores` | 分位数列改为 BLEU/Acc/F1 等指标轴 |
| `mh_red_flags` → `retraction_flags` | 心理红灯 → 撤稿/低质期刊标识 |
| `chat` 页面右侧引用栏 | 升级为**可点击回原文**的锚点列表 |

### ❌ 不搬（内容域专属，直接废弃）

- 全部职业规划内容（1092 行中约 900 行）
- 学校事实层（`school_overview`、`tuition`、`admission_*` 等 17 张表）
- 心理健康层（`mh_*` 14 张表）
- 薪资/简历/面试/权益内容

> **保留约 190 行**：即治理层的 `data_sources`(9) + `data_gaps`(15) + `kb_docs`(3)，加上结构模板。

## 五、升级点（相比路书真正新增的）

| # | 升级点 | 对应评分项 |
|---|---|---|
| 1 | **溯源颗粒度**：表行级 → 段落级 + PDF 坐标 + 文本哈希 | 抗幻觉 RAG 8% |
| 2 | **版本演进识别**：v1 vs v7 语义去重（路书无此能力） | 技术方案创新 8% |
| 3 | **冲突检测**：多篇论文结论矛盾时显式提示，不择一 | 跨文献推理 |

| 6 | **双向锚点**：正文 `[11]` ↔ References 无损跳转 | 交互创新 7% |

## 六、技术文档可用的"创新点"三条

写进技术文档「创新点说明」章节，直接对应 25% 权重：

**技术创新点 1：跨域迁移的确定性问答治理架构**
将垂直知识库场景验证过的「分层路由 + 来源分级 + 无覆盖兜底」架构，迁移至开放域学术文献场景，并证明其在低资源、高严谨度要求下的有效性。

**技术创新点 2：段落级可验证溯源（Verifiable Paragraph-level Tracing）**
不仅给出页码，还提供 `bbox 坐标 + char_span + 原文 SHA256` 三重校验。问答时可反向验证"引用的这段话确实出自该页该位置"，从机制上杜绝模型伪造引文。

**应用创新点：从"文献管理"到"研究链路闭环"**
打通「检索 → 解析 → 阅读 → 对比 → 图谱洞察 → 写作」全链路，使图谱发现的 research gap 可直接转化为写作建议，形成科研工作流闭环。

## 七、风险与对答准备（决赛答辩会被问）

| 可能被问 | 建议回答 |
|---|---|
| "这不就是个文献管理工具加个聊天框？" | 强调**三重校验的溯源机制**与**图谱驱动的 gap 发现**，这两点通用工具没有 |
| "你和 Zotero/ReadPaper 有什么区别？" | 定位不同：Zotero 管文献，我们做**推理与溯源**；且支持跨文献对比与 Future Work 去重 |
| "为什么用 Chroma 不用 Milvus？" | 如实说：本次为赛程约束下的工程取舍，架构已预留 Milvus 适配层（写出接口抽象即可） |
| "AI 写的代码你懂吗？" | 必须能讲清 anchors 数据结构、检索链路、Guardrails 触发条件——**这三处是你亲手设计的，务必背熟** |
